产品经理把需求写成文档,UI 设计师画出界面稿,接下来的工作交给前端:把静态的设计稿实现成浏览器里可以点击、可以输入的页面。这篇先从整体说明前端做什么,再沿着「输入 URL」这个动作,走完页面出现的全过程。

## 前端负责什么

浏览器里看到的一切都由前端实现:页面的结构、颜色与排版、点击按钮后的反应、数据的请求与展示,以及不同屏幕尺寸下的适配。这些工作通常归为三部分:

- 结构:用 HTML 描述页面上有什么,标题、段落、链接、图片、表单;
- 样式:用 CSS 决定它们长什么样,位置、颜色、字体、间距、动画;
- 行为:用 JavaScript 决定它们做什么,响应点击、校验输入、请求数据、更新页面。

三部分各司其职,又运行在同一个页面里。HTML 提供节点,CSS 选中节点并施加样式,JavaScript 找到节点并绑定事件、修改内容或样式。

实际工作还包括浏览器兼容、加载性能与可访问性。同一段代码在 Chrome、Safari、Firefox 中的表现可能不同,需要确认目标浏览器的支持范围;页面要在低端手机上保持可用,图片、脚本与字体的体积需要控制;键盘用户和屏幕阅读器用户同样要能完成操作。这些内容分别在第 9、15、18 章展开。

前端处在协作流程的中段。产品定义要解决的问题与流程,UI 设计确定视觉与交互稿,前端把稿子变成可运行的页面,后端提供数据与业务规则,双方通过 HTTP 接口交换数据。顺序上,需求先经过产品与 UI,再到前端;这也是本知识库把「产品 → UI → 前端」作为阅读起点的原因。前端需要理解设计稿的意图,也需要读懂接口返回的字段,但不必承担视觉决策或业务规则的实现。

## 从输入 URL 到看见页面

在地址栏输入一个地址并回车,浏览器做了下面这些事:

```text
URL 解析 → DNS 查询 → TCP 握手 / TLS 握手 → 发送 HTTP 请求 → 接收响应
→ 解析 HTML 与 CSS → 构建渲染树 → 布局与绘制 → 执行 JavaScript
```

**URL 解析。** 浏览器先把地址拆成协议、主机、端口、路径和查询参数。`https://example.com/docs?q=html` 中,`https` 是协议,`example.com` 是主机,`/docs` 是路径,`q=html` 是查询参数。协议决定了后面用什么方式通信。

**DNS 查询。** 主机名不能直接用来建立连接,需要先换成 IP 地址。DNS(Domain Name System,域名系统)负责这次查询;结果会被缓存,再次访问同一域名时通常不必重新查询。

**TCP 与 TLS。** 浏览器与目标 IP 建立 TCP 连接,保证数据按序到达。地址以 `https` 开头时,还要在 TCP 之上完成 TLS 握手,协商加密方式并验证服务器证书。HTTP 是应用层的协议,它依赖下面的连接来传输请求与响应。

**HTTP 请求与响应。** 浏览器发送请求,内容包括方法(如 `GET`)、路径、请求头和可选的请求体。服务器处理后返回状态码、响应头和响应体;响应体通常就是 HTML 文档。

**重定向与缓存。** 响应可能是 `301` 或 `302`,浏览器按 `Location` 头再发一次请求,地址栏随之更新。静态资源还可能直接命中 HTTP 缓存,不再访问服务器;DevTools 的 Network 面板会把这类请求标为 memory cache 或 disk cache,排查「改了文件却没生效」时先看这一列。

**解析与渲染。** 浏览器把 HTML 解析成 DOM 树,把 CSS 解析成 CSSOM,两者结合成渲染树,再计算每个节点的位置与大小(布局),最后绘制到屏幕上。图片、字体等资源会在这个过程中继续加载。

**JavaScript 执行。** 页面中的脚本由 JavaScript 引擎执行。浏览器既是渲染引擎的宿主,也是 JavaScript 的运行时:脚本可以读取和修改 DOM、监听事件、发起网络请求。脚本的执行会与解析、渲染相互影响,所以脚本放在哪里、是否延迟执行,都会改变页面出现的时间。

## 服务端渲染与客户端渲染

上面的流程里,HTML 有两种常见的产生方式。

- 服务端渲染(SSR):服务器直接返回已经包含内容的 HTML,浏览器收到后就能显示,JavaScript 再接管后续交互;
- 客户端渲染(CSR):服务器返回一个内容很少的 HTML 外壳,页面内容由 JavaScript 在浏览器里请求数据并生成 DOM。

两种方式各有代价:SSR 首屏内容出现得早,但服务器压力更大;CSR 交互切换快,但首屏要等脚本下载与执行。现代框架常把两者混合使用,后面第 12 章会展开。

判断一个页面用了哪种方式,可以在浏览器里禁用 JavaScript 后刷新:内容仍然显示的多半是 SSR,只剩空白或骨架的多半是 CSR。

## 先看一个最小页面

不必等环境配好,先写一个 HTML 文件,确认浏览器能显示它:

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>第一个页面</title>
</head>
<body>
  <h1>你好,前端</h1>
  <p>这一行由 HTML 写在页面里。</p>
</body>
</html>
```

文件里的四个部分各有一项职责:

| 部分 | 作用 |
| --- | --- |
| `<!doctype html>` | 告诉浏览器按标准模式解析文档 |
| `<html lang="zh-CN">` | 文档根节点,并声明页面语言 |
| `<head>` | 元信息与资源引用,不直接显示在页面上 |
| `<body>` | 可见内容,标题与段落都写在这里 |

把内容保存为 `index.html`,用浏览器打开。预期结果是:标签页标题显示「第一个页面」,页面里有一行大标题「你好,前端」和一段文字。页面上没有样式,也没有交互,它只证明了结构这一层已经生效。下一篇准备编辑器与 DevTools,再补充样式与行为。

这个文件在任何现代浏览器里都能直接打开,不需要服务器。它的作用是确认编辑器、保存路径与浏览器三者都在正常工作。

## 小结

- 前端把设计稿实现为可交互页面,工作分为结构(HTML)、样式(CSS)、行为(JavaScript);
- 输入 URL 后,浏览器依次完成 URL 解析、DNS、TCP/TLS、HTTP 请求与响应、解析与渲染、JS 执行;
- HTTP 是应用层协议,依赖 TCP/TLS 连接传输请求与响应;
- 服务端渲染返回含内容的 HTML,客户端渲染由 JS 生成页面内容;
- 一个最小的 HTML 文件就能验证结构层,后续再补样式与行为。
