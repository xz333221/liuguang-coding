第一个页面已经能点击、能计数,接下来要决定按什么顺序读完剩下的 19 章。这份知识库把前端拆成 20 章,从结构与样式一直讲到框架、性能与上线。先给结论:不必从第 1 章逐篇读到第 20 章,按目标选入口,再把缺口补齐。

## 目录怎么用

侧栏目录分四层:方向 → 章 → 节 → 小节。前端是其中一个方向,下面挂 20 章。编号由目录树的位置自动计算,例如 2、2.3、2.3.1,编号本身就是建议的阅读顺序。

几个使用细节:

- 章节点可以折叠,当前阅读路径会自动展开,折叠状态会被记住;
- 「筹备中」表示这一节还没有文章,目录先立起来,补上内容后标记自动消失;
- 正文里带下划线的术语,悬停有一句解释,点击进入术语表的完整说明;
- 每篇页脚列出参考资料,想核对某个说法可以按链接继续读;
- 部分文章配有思维导图,出现在正文上方;文章头部的「问这篇」可以就当前内容提问。

章节之间存在依赖,但不必等一章完全掌握再进入下一章。读到第 4 章布局时如果对选择器还不熟,可以回到第 3 章查对应小节;第 12 章框架里的模板语法,也会反复用到第 2、3 章的结构与样式知识。

```text
结构 → 样式 → 行为 → 浏览器 → 工程化 → 框架 → 质量 → 实战
```

## 按目标选入口

**零基础,第一次接触前端。** 按编号走:1 → 2 → 3 → 4 → 6 → 8。先把结构、样式和最基本的脚本学完,能做出一个静态页面;第 5 章(CSS 进阶)和第 7 章(异步)可以等做过页面再补。

**会一点 JavaScript。** 从第 2 章快速过一遍 HTML,第 3、4 章重点读 CSS 的层叠与布局,第 6 章核对语言细节,然后直接进入第 8 章 DOM 与第 12 章框架。第 7 章的异步模型在框架开发中每天都会用到,不能跳过。

**后端转前端。** HTTP、状态码、缓存这些概念已经熟悉,可以压缩第 9 章,把时间放在第 3、4 章的层叠与布局、第 8 章的 DOM 事件,以及第 12 章的状态到视图同步。前端与后端最大的差异在渲染与交互,不在网络层。

**只想做出页面。** 读 2 → 3 → 4 → 6 → 8,再按需看第 12 章。这个顺序足以完成结构清晰、能在手机和桌面显示的页面;性能、测试与安全等章节等有真实项目再读。

如果暂时不确定目标,先按零基础路线走完 2-8 章,再根据项目需要补后面的章节。

```bash
mkdir frontend-practice
cd frontend-practice
npx serve .
```

无论选哪条路线,都建议建一个练习目录,把每章的示例放进去,用本地服务器打开。目录会随着章节推进变成一个可回看的作品集。

## 练习方法

前端的很多概念需要在页面里验证,只看不写很难建立准确的直觉。每章至少做三件事:

1. 把正文里的代码原样运行一遍,确认输出与文中描述一致;
2. 改一处结构、一处样式、一处行为,观察页面如何变化;
3. 用 DevTools 验证结果:在 Elements 里看节点与规则,在 Console 里看输出与报错,在 Network 里看请求。

遇到报错先读 Console 的第一行,它通常指明了文件名、行号和错误类型。修不掉就缩小范围:注释掉最近改动的一段,确认问题是否仍然存在。这个习惯比记住 API 更有用。

还有一条建议:每学完一章,用该章的知识做一个独立的小页面。第 2 章做一份个人介绍,第 3、4 章把它排版成两栏,第 6、8 章加一个交互,第 12 章改写成组件。同一个页面反复迭代,比每章新建一个互不相关的示例更能暴露知识之间的连接。

## 小结

- 20 章按依赖排列,编号即建议顺序,不必逐章通读;
- 路线是结构与样式 → JavaScript 与浏览器 → 工程化与类型 → 框架与数据 → 质量与实战;
- 零基础从 1 开始,有 JavaScript 基础从 2、3、4、6 进入,后端转前端压缩网络部分,只想做页面读 2 到 8;
- 每章动手运行、修改并用 DevTools 验证,报错先看 Console;
- 路线选定后进入第 2 章 HTML:先把结构写对,再学样式与行为。
