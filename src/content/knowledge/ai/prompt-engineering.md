先把结论说清楚:**提示词改的是模型看到的前文,模型的参数一动不动。** 所有提示词技巧——角色、示例、思维链、格式约束——作用的都是同一件事:让"猜下一个词"这个动作发生在更明确的前提下。

这也划出了提示词工程的能力边界:它能决定模型怎么答,能多大程度改变模型会什么。

## 提示词在链路里的位置

一次请求送进模型的,通常是一串带角色划分的消息:

```text
system    你是客服助理,只依据给定资料回答
user      你们支持七天无理由退货吗?
assistant (之前的回答)
user      那运费谁出?
```

它们在推理时拼成一段上下文,模型读完这段上下文,开始逐 token 生成。**提示词是这段上下文的全部内容**,除了它,模型这一轮看不到任何别的东西——你写在注释里的需求、口头交代过的背景,只要没进消息里,就不存在。

## 四个基本手段

### 把任务说清楚

最省事的技巧是把要求写成正面、具体的陈述:"用三句话回答""按时间顺序列出""每个结论附上材料原文"。模型对模糊指令的补全方式就是猜,猜的方向常常不合预期。

有个反直觉的点:**提示词写长本身没有价值**。一段五百字的背景描述,信息量可能不如三行"任务 + 边界 + 格式"。每一句都问自己"这句话改变了模型的哪个判断",答不上来就删掉。

### 角色设定

"你是一位资深后端工程师"这类角色提示,给的是回答的口吻、视角与默认取舍:它会影响模型选词的深浅、先考虑哪些方面。角色设定改变的是表达立场,模型没学过的知识,不会因为换个角色就出现。

### 给示例

任务形状讲不清的时候,示例比描述管用。少样本提示的做法是在提示里放几组"输入 → 输出":

```text
把用户反馈分成 功能建议 / 缺陷 / 咨询 三类。

反馈:导出报表的时候点一下就卡死
分类:缺陷

反馈:希望支持按部门筛选
分类:功能建议

反馈:这个按钮点了没反应啊
分类:
```

示例给的是三样东西:**格式**(输出长什么样)、**粒度**(一类和多类的边界在哪)、**风格**(严谨还是随意)。一个示例都不给、全靠任务描述的叫零样本提示;描述得清楚时它够用,边界模糊时补两三个示例,效果通常立刻稳定下来。

### 思维链

让模型把推理步骤一步步写出来再给结论,就是思维链。它的收益在多步任务上最明显:

```text
直接答:一个订单 3 件商品,每件 47 元,满 100 减 30,应付多少?
先分步:1) 3 × 47 = 141 元;2) 141 满 100,减 30;3) 141 − 30 = 111 元
```

步骤摊开之后,每一步都可以被检查,后续步骤也能踩着前面的中间结果走。代价是输出变长、延迟和费用上升,所以简单任务(分类、抽取、改写)开思维链是浪费。

注意区分:思维链是**提示层**的技巧,你在提示里求它"一步步想";而推理模型把中间推理练进了模型本身,行为由训练塑造。后者不开任何提示也会展开推理。

## 让模型按格式交结果

要 JSON、要表格、要固定字段,做法按可靠程度从低到高排:

1. **文字描述**:说清字段名、类型、缺省值怎么填。简单场景够用。
2. **给示例**:贴一段期望输出的样例,模型照着形状填。这是最稳的提示层手段。
3. **接口约束**:用 JSON mode,或把输出 schema 写进工具调用的参数里,由接口层强约束格式。

只靠"请务必输出合法 JSON"这种强调,稳定不住;把期望的样子摆给它看,再让接口兜底,才是工程上的完整做法。解析失败时,把报错信息回给模型让它重生成,比直接抛给用户好。

## 压住无据生成

模型按概率续写,保证的是通顺,不是属实。让它依据材料回答,三个动作最直接:

- **明确指令**:"只依据下列材料回答,材料里没有就回答'资料不足'"。关键是给一个"没依据就明说"的出口,模型被逼着填时才会编。
- **要求引用**:让答案附上依据出自哪段材料,模型对没依据的内容自然更难张口。
- **控制温度**:抽取、问答这类要稳的任务,温度压低能减少随机发挥。温度管的是采样随机性,管不了依据——真正兜底的还是前两条。

要彻底一点,把检索(RAG)接上,让材料以可控的方式进入上下文,见《检索增强生成:先查资料再回答》。

## 参数与提示词的配合

提示词和采样参数是两套旋钮,各管一段:

| 手段 | 改变的东西 | 生效范围 |
| --- | --- | --- |
| 提示词、示例、结构 | 模型看到的前文 | 这一次请求 |
| 温度、top-p | 从分布里抽签的方式 | 这一次请求 |
| 微调 | 模型参数本身 | 之后所有请求 |

调参顺序上,先把提示词和资料喂对,再动温度。提示词没写清楚时,温度调到 0 也只是稳定地给出一个错得一致的答案。

## 面试常问的三个判断

1. **"提示词能改变模型能力吗?"** 改变的是条件与引导,能力上限来自参数与训练。提示词能逼近上限,稳定的能力差距要靠换模型或微调。
2. **"system prompt 写进前端安全吗?"** 提示词本身不是密钥,但别把 API 密钥和内部规则一起塞进前端——前端代码对所有人可见,密钥泄露等于门户大开。密钥留在服务端。
3. **"提示词越长越好吗?"** 每一句都要改变模型的某个判断才有价值。废话占着窗口,还把关键指令稀释了。

## 一句话记住

**提示词工程是在不碰参数的前提下,把任务、边界与格式讲清楚**。示例给形状,指令给边界,思维链给中间步骤,接口约束给格式——手段不同,作用的都是模型开始猜下一个词之前看到的那段前文。
