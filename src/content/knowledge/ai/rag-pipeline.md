先把结论说清楚:**RAG 在生成之前插了一道检索**。用户提问时,先从资料库里召回相关片段,拼进提示,模型依据这些资料回答。模型没见过的私有内容、刚更新的业务知识,靠这条路进上下文,参数一动不动。

## 链路全貌

一条最小可用的 RAG 链路分两段——入库(离线)和查询(在线):

```text
入库:文档 → 清洗 → 切分 → 向量化 → 写索引
查询:问题 → 向量化 → 召回 Top-K → 重排 → 截断 → 拼提示 → 生成
```

入库做一次,查询每次提问都走一遍。链路每一环都会在最终答案里留下痕迹,**答非所问时先拆链路,再调模型**。

## 第一环:资料要变成可检索的文本

链路的起点是"资料变成文本"。这一环的坑最容易被跳过:

- **扫描件、图片不过 OCR,后面全白做**。检索再准,也召不出图片里没识别的字。
- **表格、公式、多栏排版**要专门处理。直接抽文本会把表格抽成乱序的行,问题和答案对不上。
- **格式噪音**要清:页眉页脚、导航文字、重复的免责声明,混进索引会稀释相似度。

判断标准很直接:**你人工在资料里找得到答案,检索才可能找得到。**

## 第二环:切分决定检索的最小单位

长文档要先切成小块才能入库。切分策略直接决定召回质量:

- **切太大**:一个块里话题混杂,嵌入把多种意思平均成一个向量,查询和谁的相似度都不高。
- **切太小**:关键句被拦腰切断,"报废率 3.2%"的数字断在另一块里,召回了也拼不出完整答案。
- **常见做法**:按文档结构(标题、段落、列表项)切,块与块之间保留一小段重叠,避免边界切断语义。

粒度没有标准答案,拿真实问题跑召回看结果,比拍脑袋定 512 还是 1024 快。

## 第三环:向量化与召回

每个块算一个 embedding,和原文一起存进向量数据库。查询来了,同样算 embedding,按相似度找最近的 K 个块。这一环的两个要点:

**向量检索擅长意会,短于精确。** "怎么提高良率"能召回"提升合格率的方法",意思想近就沾;但"BX-207 型号"这种编号、型号、专有名词,向量常常对不上号——这时关键词检索(如 BM25)反而一打一个准。所以生产上常用**混合检索**:两路各召回一批,合并后统一排序。

**召回是近似最近邻,排序粗。** 向量索引为了速度牺牲了精度,召回几十条里的顺序只能算粗排。后面通常接一个**重排**模型,对候选逐条精细打分,只把前几名(常见 3 到 8 个块)送给模型。粗排求全,精排求准,两道工序各管一段。

## 第四环:拼进提示,让模型照着答

召回片段只是原料,怎么进提示同样影响答案:

```text
system:你是问答助手,只依据【资料】回答,资料里没有就回答"资料不足"。

【资料】
[1] ...召回片段一...
[2] ...召回片段二...

用户:去年我们厂的报废率是多少?
```

三个细节值得注意:

1. **给"没依据就明说"的出口**。这是压住无据生成最直接的手段,模型被逼着填时才会编。
2. **标注编号,要求引用**。让答案带上依据编号,既方便用户核对,也倒逼模型贴着资料写。
3. **片段顺序有讲究**。研究发现关键信息放在上下文中间时使用率会下降——最相关的片段放首尾,比按相似度顺序平铺更稳。

## 翻车点都长在链路上

RAG 效果出问题,九成在检索侧,按排查顺序列一遍:

| 现象 | 先查 |
| --- | --- |
| 完全召不回东西 | 资料是否变成文本(OCR/解析),索引是否写入 |
| 召回了,答案漏关键数字 | 切块是否把关键句切断,关键块是否被截断在 Top-K 外 |
| 答案对,依据张冠李戴 | 重排是否缺失,编号与片段对应关系 |
| 资料里明明有,模型说没有 | 提示是否给了"不知道"出口,片段是否被稀释在过长的上下文里 |
| 编号类查询老是跑偏 | 换混合检索,补关键词一路 |

先看**真正喂进模型的那段上下文**,再动模型。把每次请求的召回片段落日志,是排查 RAG 问题最值钱的一个习惯。

## RAG 和微调的分工

两条路都能让模型"懂你的业务",分工很清楚:

| | RAG | 微调 |
| --- | --- | --- |
| 注入的东西 | 可检索的资料 | 行为、格式、风格 |
| 知识更新 | 改索引即可,分钟级生效 | 重新训练,天级生效 |
| 知识形态 | 原文可溯源 | 融进参数,不可逐条核对 |
| 主要成本 | 检索基建 + 每次查询的 token | 训练算力 + 数据标注 |

**频繁变化的知识走检索,稳定的行为规范走微调。** 两边互不替代,常见做法是 RAG 管知识、微调管格式,叠加使用。

## 一句话记住

**RAG 是把"查资料"接在生成之前:先召回,再回答。** 链路每一环都会在答案里留痕——资料要能检索、切分要保语义、召回要混合、结果要重排、提示要给出口。答非所问时,先拆链路,再调模型。
