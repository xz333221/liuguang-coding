先把结论说清楚:**注意力做的事是加权求和。** 一个位置上的新表示，等于上下文里所有位置的信息，各自乘上一个"该看多重"的权重，再加起来。

这个权重由模型自己算出来:每个词发出一个提问(query)，去和上下文里每个词的标签(key)比对，越对得上，就越多地取用那个词的内容(value)。

## 为什么不用循环

在注意力之前，处理序列的主流做法是循环网络:一个词一个词往前推，把历史压进一个隐藏状态。两个毛病很明显:

- **必须按顺序算**，前一步没算完后一步起不来，训练时用不上并行的显卡;
- **距离一长就忘**。信息要走很多步才能从句子开头传到结尾，中间越传越淡。

注意力换了个思路:让任意两个位置**直接建立联系**，一次算清所有两两的相关度。于是:

- 所有位置的运算彼此独立，可以**并行**;
- 两词之间的距离是 1 步还是 100 步，取用时没有本质差别。

## 三个角色:Query、Key、Value

用一个检索的类比最容易记住:

| 角色 | 类比 | 作用 |
| --- | --- | --- |
| Query(Q) | 我要找什么 | 当前词发出的提问 |
| Key(K) | 每份资料的标签 | 每个词拿出的"自我介绍" |
| Value(V) | 资料的内容 | 每个词真正要贡献的信息 |

原始论文里，Q、K、V 都是由同一个输入分别乘上三个可学习的权重矩阵得到的:

```text
Q = X · W_q      K = X · W_k      V = X · W_v
```

`X` 是这一层的输入(每个词一行向量)，`W_q` / `W_k` / `W_v` 是训练出来的参数。**同一份输入，投影到三个不同的空间**:有的角度用来提问，有的角度用来当标签，有的角度用来当内容。

## 计算就四步

以"一个词该从上下文里取多少信息"为例:

1. **打分**:拿它的 query 和每个词的 key 做**点积**。点积越大，方向越一致，说明越相关。
2. **缩放**:乘上 `1 / √d_k`，`d_k` 是向量的维度。这一步是为了压住数值。
3. **归一化**:对着一行分数做 softmax，变成一组和为 1 的权重。
4. **加权求和**:用这组权重去混合所有词的 value，得到这个词的新表示。

写成公式:

```text
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V
```

用 Python 和 NumPy 手写一遍，一共就这么几行:

```python
import numpy as np

def softmax(x):
    x = x - x.max(axis=-1, keepdims=True)   # 减去最大值防溢出，结果不变
    e = np.exp(x)
    return e / e.sum(axis=-1, keepdims=True)

def attention(Q, K, V):
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)   # 每个 query 对每个 key 打分
    weights = softmax(scores)         # 每行归一化，和为 1
    return weights @ V                # 按权重混合 value
```

对一个 4 个词的句子，`scores` 是个 4×4 的矩阵:第 i 行第 j 列，就是"第 i 个词有多在意第 j 个词"。softmax 之后，每一行变成一个概率分布。

## 为什么要除以 √d_k

不缩放会怎样？假设 query 与 key 的每一维都独立、均值 0、方差 1，那么它们的点积是 `d_k` 个乘积之和，**方差会随维度线性增长**，数值范围大致在 `±√d_k` 附近。

维度一高，点积的绝对值就变大，softmax 被推向"某个位置接近 1、其余接近 0"的极端。这时 softmax 的梯度会变得极小，训练就卡住了。除以 `√d_k` 正好把方差拉回 1 附近，让分布保持在有梯度的区间里。论文里称之为 scaled dot-product，这个 scale 就是它的来处。

## 多头:同时从几个角度看

一个注意力头只能输出一种"相关性视角"。论文的做法是并行跑好几组 Q/K/V 投影，也就是**多头注意力**:

- 每个头有自己的 `W_q / W_k / W_v`，学到不同的关注模式:有的盯语法搭配，有的盯指代关系，有的盯邻近词;
- 每个头在更低的维度里算(比如总维度 512 分成 8 个头，每个头 64 维);
- 最后把所有头的输出拼起来，再过一个线性层。

总计算量和一个单头大注意力差不多，但模型能同时表达多种关系。

## 词序要额外补进去

自注意力本身只看"谁和谁相关"，**不包含任何位置信息**。把词序打乱，每个词拿到的仍是同一批邻居，只是排列变了，模型分不出"猫追狗"和"狗追猫"。

所以要在输入里补上位置:早期用正弦函数编码位置(论文里的做法)，后来也有可学习的位置向量，现在主流的大模型多用**旋转位置编码(RoPE)**:把位置信息以旋转的方式编进 query 和 key 里，让点积天然带上相对距离的含义。

## 生成时不能偷看未来

自回归生成是一个词一个词往外吐的:算第 i 个位置的表示时，第 i 个位置之后的词还不存在。但注意力公式是对全序列算的，直接算就会偷看答案。

解决办法是**因果掩码**:在 softmax 之前，把"未来"那些位置的分数设成负无穷，softmax 之后它们的权重就是 0。这样每个位置只看自己和它左边。

## 代价在 O(n²)

`Q·Kᵀ` 是一张 n×n 的分数矩阵。序列长度每翻一倍，这张表就大四倍，计算量和显存占用都跟着涨。**上下文窗口之所以贵、之所以有长度上限，根子就在这里。**

后面各种"高效注意力"，思路都是绕开这张完整的 n×n 表:滑动窗口只算邻近的一段、稀疏注意力只保留部分连接、或者用近似方法降维。它们牺牲一点精度，换长度。

## 四个常见误解

1. **"注意力权重就是模型给出的解释"**。权重确实表示"这一步取用了谁多少"，但它只是某一层、某一个头在某一层的中间量。拿它当模型决策的理由要谨慎。
2. **"注意力就是查字典"**。类比里的 query/key/value 是**训练出来的投影**，模型学到的"相关性"未必对应人类语义。
3. **"多头是简单复制"**。每个头的参数独立，学到的模式不同;头与头之间还会互相冗余，剪掉一些头常常不怎么掉点。
4. **"词越多越准"**。上下文变长会让注意力被摊薄，关键信息容易被淹没，这就是"大海捞针"评测关心的现象。放进去不等于用得上。

## 一句话总结

**注意力 = 按相关度给上下文加权求和。** query 提问、key 应答、value 提供内容，缩放点积之后 softmax 成权重，再混合成新的表示。理解这条链，多头、位置编码、因果掩码、以及 O(n²) 的代价，都是从它自然推出来的。
