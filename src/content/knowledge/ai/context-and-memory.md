先把结论说清楚:**模型每一轮能看到的,只有你这次送进窗口的那串 token。** 窗口有上限,注意力的计算量随长度平方增长,所以窗口又小又贵。上下文的组织方式——放什么、怎么裁、跨会话记什么——直接决定模型答得好不好。

## 窗口为什么是稀缺资源

上下文窗口是模型一次前向计算能处理的 token 总量,超出的部分它看不到。三条约束叠在一起:

- **注意力对序列长度是 O(n²)**。窗口翻倍,注意力的计算量翻四倍,这是窗口又贵又有限的根源。
- **生成是自回归的**,每步都要重看整段上下文。历史越长,每一轮的成本越高,而且按轮数线性累加。
- **"看得到"和"用得上"是两件事**。研究发现,关键信息放在上下文中间时,模型对它的使用率明显下降——俗称"中间迷失"。塞满不等于用上。

结论很直接:**窗口里的每个 token 都在花两份钱**——推理成本一份,注意力稀释一份。所以要做上下文工程:检索、重排、摘要、裁剪,把窗口留给最相关的信息。

## 一次请求的窗口怎么排

一个多轮应用每次请求拼进去的内容,大致是这几层:

```text
┌─────────────────────────────┐
│ system 提示:角色、规则、格式   │  ← 每轮都在,写精简短小
├─────────────────────────────┤
│ 检索/工具注入的资料           │  ← 按当前问题动态取,用完可清
├─────────────────────────────┤
│ 历史对话(或它的摘要)          │  ← 会长大的那一层,重点管理对象
├─────────────────────────────┤
│ 当前用户消息 + 输出格式要求    │  ← 最后放,离生成最近,权重最高
└─────────────────────────────┘
```

排布讲究两条:**稳定的放前面,易变的放后面**。system 提示每轮不变,放最前面;当前问题离生成位置最近,放最后。中间的检索资料和历史,是长度不可控的两层,也是工程的主战场。

## 历史对话:三种管法

多轮对话里,历史是唯一会无限增长的部分。常见三种策略,按代价从低到高:

| 策略 | 做法 | 适合 |
| --- | --- | --- |
| 全量带 | 每轮把完整历史原样重发 | 短会话、调试期 |
| 滑动窗口 | 只保留最近 N 轮,更早的丢弃 | 任务型对话,早期内容确实无关 |
| 滚动摘要 | 把老历史压成几条要点,近期几轮保留原文 | 长会话,早期结论还要用 |

滑动窗口的坑在"丢掉的正好是关键前提"——用户第一句定的需求,聊到第二十轮时被窗口裁掉了。滚动摘要的代价是每压一次都要花一轮模型调用,换来的是关键结论以要点的形式活着。

工程上的常见组合:**system 提示压到最短 + 老历史滚动摘要 + 最近几轮原文 + 当前问题**。窗口占用从"随轮数线性膨胀"变成"接近一个常数"。

## 跨会话的记忆

窗口里的内容,请求一结束就没了。用户换个会话再来的偏好、事实、约定,要记住就得存到模型外面。记忆机制的常见分层:

- **短期记忆**:当前会话的上下文窗口,会话结束即消失。
- **长期记忆**:落到外部存储(数据库、向量库、文件)的事实与偏好,每次请求按需检索回来,注入上下文。

写入长期记忆的典型动作:

```text
用户:"以后回答都控制在三行内"
     ↓ 抽取成一条偏好
{ 用户: u_1024, 偏好: "回答控制在三行内", 更新时间: ... }
     ↓ 之后每次请求,相关偏好被检索注入 system 段
```

检索"哪些记忆这次用得上",常见做法是把记忆也做 embedding 存进向量库,按当前问题召回;用户级的固定偏好(称呼、语言、格式要求)也可以直接放在每轮都注入的位置,省掉检索。

记忆带来的新问题也要接住:**写什么**(别把闲聊当事实存)、**何时更新**(用户改口了旧记忆要失效)、**隐私**(记忆里是用户数据,存储要加密、可删除)。这三件事在面试里比"怎么检索"更容易被追问。

## 工具结果也要做上下文工程

和检索资料一个道理:工具一次返回三万行 JSON,原样塞进窗口,既挤占关键信息又推高成本。工具侧先做裁剪——字段筛选、分页、摘要——只把必要的那部分回给模型。原则和窗口排布一致:**每一段进窗口的内容,都要过一遍"这轮用得上吗"**。

## 三个常见误解

1. **"窗口开到最大,把所有资料塞进去就行。"** 注意力是平方开销,成本超线性;而且信息一多,关键内容被稀释,模型对放中间的资料使用率还会下降。塞满不等于用上。
2. **"模型记得我们上次聊了什么。"** 每一轮请求都是独立的,模型本身不存任何会话状态。连续性全靠你把历史重新送进窗口。
3. **"把历史原样重发最保险。"** 长会话里原样重发既费 token,又可能把最早的关键结论稀释掉。摘要 + 近期原文的组合,通常比全量带更稳也更省。

## 一句话记住

**上下文工程的核心问题是"这一次窗口里放什么"**。历史会摘要、资料会检索、工具结果会裁剪——一切手段都是把有限的窗口留给最相关的信息;跨会话的记忆,则要靠模型外面的存储与检索。
