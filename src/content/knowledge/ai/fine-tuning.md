先把结论说清楚:**微调改变的是模型参数本身**——用一批"问题 → 标准答案"的样本继续训练,让模型把这些样本里呈现的格式、口吻、边界学进去。提示词改输入,微调改模型,两者作用于完全不同的层。

## 微调在教什么:形式,不是事实

SFT(监督微调)的训练数据长这样:

```json
{"messages": [
  {"role": "user", "content": "把这段反馈分类:导出报表卡死"},
  {"role": "assistant", "content": "{\"类别\": \"缺陷\", \"说明\": \"导出功能无响应\"}"}
]}
```

成千上万条这样的样本过一遍,模型学到的是**回答的形式**:用 JSON、用这个字段名、这个口吻、这个边界(不确定时怎么说)。LIMA 那篇论文有个反直觉的发现:几千条高质量样本,就足以把格式与风格教得服服帖帖——微调对"形式"的效率极高。

而它对"事实"的效率极低。想让模型记住"我厂 2026 年的报废率是 3.2%",微调是条绕路:知识以分布式的形式融进参数,不可逐条核对,更新一次要重训,还容易**灾难性遗忘**——新数据训完,原来会的东西忘了。

这就划出了微调与 RAG 的分工:

| | 微调(SFT) | RAG |
| --- | --- | --- |
| 改变的东西 | 模型参数(怎么答) | 上下文内容(拿什么答) |
| 擅长 | 格式、口吻、领域行为规范 | 事实、数据、频繁更新的知识 |
| 更新成本 | 重新训练,天级 | 改索引,分钟级 |
| 可核对性 | 融进参数,不可逐条查 | 原文可溯源 |

**频繁变的知识走检索,稳定的行为走微调,两边叠加是常态。**

## LoRA:只训一组增量

全量微调更新模型全部参数,上限高,代价也实打实:优化器状态、梯度、参数副本,显存占用是模型本身的好几倍,7B 的模型想全量微调,消费级显卡基本不用想。

LoRA 的思路是**冻结原权重,只训练一组低秩增量**。观察到微调时的权重更新 ΔW 天生是低秩的,于是把它分解成两个小矩阵的乘积,只训这两个小矩阵:

```text
原权重 W(冻结不动)
增量 ΔW = B × A(只训这两个,参数量不到原权的 1%)
前向:输出 = W·x + (B×A)·x
```

收益是三重:显存大降(优化器状态只给增量)、存储小(每个任务一个几 MB 到几十 MB 的适配器)、可插拔(基座不动,换任务换适配器,回滚就是拔掉)。

**选型判断:资源有限、要多任务迭代、要易回滚,LoRA 是默认答案;追求极限效果且算力管够,才上全量。** 实践中大量"全量才行的场景",用数据质量补一补,LoRA 也能追上。

## 一条务实的决策链

模型行为不符合预期时,按代价从低到高试:

1. **提示词 + 示例**:改输入,零训练成本。给示例、给格式、给边界,大多数"格式老是不对"在这一层就解决了。
2. **上下文工程**:资料喂对、历史管好、工具结果裁过。属于"答案的原料"层。
3. **少量样本 SFT**:提示层确实稳不下来的行为(内部规范格式、固定口吻),用几百到几千条规范样例微调。数据质量胜过数量,标注时多花的心力都算数。
4. **考虑更大模型 / RAG**:能力不够是另一回事,那不在微调射程内——换模型或补检索。

这个顺序的理由很简单:**越靠前的手段,迭代越快、回滚越便宜。** 微调是重武器,留给提示层确实解决不了的稳定行为。

## 微调之后的世界线

微调上线,有几件事要接着接住:

- **评测先行**。没有"微调前后哪个好"的量化对比,微调就是玄学。攒一批真实问题的期望输出当评测集,每次微调跑分再上线。
- **幻觉不会消失**。微调能降低特定场景的出错率,最终兜底还是检索、格式约束、结果校验那套。
- **基座与适配器要版本化**。哪个基座、哪个适配器、哪份数据训的,记不清就没法复现问题。

## 面试常问的三个判断

1. **"SFT 和 RAG 怎么选?"** 教行为规范用 SFT,注入频繁更新的事实用 RAG。微调教"怎么答",检索管"拿什么答",互不替代。
2. **"LoRA 为什么省资源?"** 冻结原权重,只训低秩增量——优化器状态和存储都只给增量部分,基座可多任务共享。
3. **"微调能治好幻觉吗?"** 能降低特定场景出错率,治不了根。幻觉是生成机制的固有倾向,最终靠检索、约束与校验兜底。

## 一句话记住

**微调改的是模型参数,SFT 教的是回答的形式:格式、口吻、边界。** 事实与频繁更新的知识交给检索;提示层稳不下来的稳定行为,才用少量高质量样本加 LoRA 去做——而且评测要先于训练。
