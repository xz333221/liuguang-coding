先把结论说清楚:**这些框架按战场分四类——编排链路的、管数据检索的、玩多 Agent 的、可视化搭应用的。** 选型的第一步不是比功能列表,是看你的任务形态落在哪一类;第二步看可控性与迁移成本。

## 一张表看清战场

| 框架 | 战场 | 核心抽象 | 什么时候找它 |
| --- | --- | --- | --- |
| LangChain | 编排 | 组件 + 链 | 快速拼装模型调用、提示、工具的流水线 |
| LangGraph | 编排 | 节点 + 边 + 状态 | 有条件分支、要循环和回退的 Agent |
| LlamaIndex | 数据 | 索引 + 查询引擎 | RAG:文档接入、切分、检索 |
| AutoGen | 多 Agent | 对话协议 | 多角色按对话规则协作 |
| MetaGPT | 多 Agent | 角色化流程(SOP) | 按软件公司分工模式组织任务 |
| Dify / Coze | 低代码平台 | 可视化配置 | 快速验证、内部工具、不懂代码的同事也能改 |
| AutoGPT | (历史项目) | 自主循环 | 了解 Agent 演进;生产直接用的少 |

注意 AutoGPT 的位置:它证明了"定个目标,Agent 自己拆自己跑"的潜力,也把目标漂移、成本失控、可靠性不足的问题全部暴露了一遍。今天的生产 Agent 设计里那些约束(检查点、终止条件、人工兜底),相当一部分是从踩它的坑里长出来的。

## 编排类:LangChain 与 LangGraph

两者同出一家,定位递进。LangChain 把模型调用、提示模板、工具、检索都做成组件,用链串起来,适合快速拼装固定流水线;问题在复杂流程上——条件分支、循环、回退用链表达很别扭,代码容易绕成一团。

LangGraph 把流程表达成**图**:节点是一个处理步骤,边是步骤间的走向,状态在图上流转。它补的正是链缺的三样:**条件分支**(走到哪看状态)、**循环**(不满足就回去重做)、**检查点**(每步存状态,可中断可恢复)。

判断很直接:**流程是直的,用链;流程有分支、有回退,上图。** 今天新起的 Agent 项目,社区普遍建议直接从 LangGraph 出发,链的迁移成本比想象中低。

## 数据类:LlamaIndex

LlamaIndex 的主战场在数据侧:上百种文档连接器(Notion、S3、PDF、数据库)、切分策略、多种索引、查询引擎,把私有资料变成模型能查的知识。RAG 链路里"入库"那一半,它给得最全。

它和编排框架是搭档,不是对手:常见组合是 LlamaIndex 管检索,LangChain/LangGraph 管流程。只做问答机器人、流程极简时,单用 LlamaIndex 就够。

## 多 Agent 类:AutoGen 与 MetaGPT

两者的核心抽象差异,比名字差异更值得记住:

- **AutoGen 偏对话协议**:定义好几个角色(助理、审查者、工具执行者)和对话规则,让它们按协议轮流发言。灵活,终止条件要自己管严。
- **MetaGPT 偏角色化流程**:把软件公司的 SOP 形式化——产品经理出需求文档、架构师出设计、工程师写代码,按固定顺序交接。论文里的核心动机是"SOP 减少幻觉":结构化交接比自由对话更稳。

共同点是都给"多个模型实例怎么协作"提供了基础设施;共同短板是任务拆解合理性、终止严格度、消息 schema 这些真正的质量来源,框架都不替你想。

## 低代码平台:Dify 与 Coze

这类平台把提示管理、知识库、工具、工作流做成可视化拖拽,能直接发布成应用。适合三种场景:**快速验证**(半天搭出可用的问答机器人看效果)、**内部工具**(运营同学自己改提示,不占研发排期)、**原型演示**。

边界也要清楚:深度定制(复杂状态管理、私有协议、精细的容错)到头来还是要写代码;提示词、知识库、评测集沉淀在平台里,换框架时有迁移成本。**把核心资产(提示、评测集)整理成与框架无关的数据文件,是给自己留的后路。**

## 选型的判断顺序

面试或实战里被问"选哪个框架",按这个顺序答,比直接报名字稳:

1. **先问任务形态**:固定流水线 / 带分支的 Agent / 重检索的问答 / 多角色协作,四种形态对应四类框架。
2. **再问可控性要求**:流程要能审查、能回退、能人工介入,图编排(或干脆自研状态机)比对话协议更稳。
3. **再问团队与周期**:两周要demo,平台优先;长期演进的核心链路,代码框架优先。
4. **最后留后路**:提示、知识库、评测集与框架解耦,换框架时这些资产要能带走。

补一个生产环境的真实倾向:Anthropic 公开的多 Agent 系统复盘里提到,他们最终**自管状态机、框架只用在模型调用层**——当流程复杂到需要精细控制每一跳时,薄封装比厚框架更好查错。这不否定框架的价值(快速起步、生态组件),它标出的是复杂度天花板所在。

## 面试常问的三个判断

1. **"LangGraph 和 LangChain 什么关系?"** 同生态,定位递进:链适合直线流水线,图把流程表达为节点与边,支持状态、循环、检查点与人工介入。
2. **"Dify 这类平台会取代写代码吗?"** 快速验证与内部工具上是利器;深度定制、复杂流程、精细容错仍要代码。资产与平台解耦,换得动才用得放心。
3. **"AutoGPT 能直接上生产吗?"** 它暴露的可靠性问题(目标漂移、成本失控)正是生产 Agent 要逐项补的:终止条件、检查点、预算上限、人工兜底。

## 一句话记住

**框架按战场分四类,选型先看任务形态,再看可控性,最后给自己留迁移的后路。** 流程直用链、流程曲用图、重检索找 LlamaIndex、多角色找 AutoGen/MetaGPT、赶时间上平台——而复杂度到头时,薄封装 + 自管状态机往往是终点。
