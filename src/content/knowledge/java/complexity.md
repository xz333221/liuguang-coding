上一篇讲完分层与防腐层:依赖方向朝内,外部实现挡在边界之外。业务结构安顿好之后,还有一个经常被忽略的维度:同一个功能换一种写法,运行时间可能差出几个数量级。这一章先讲怎么估算这个差距。

## 复杂度衡量的是什么

复杂度描述算法消耗的资源随输入规模增长的趋势,不描述某台机器上的绝对耗时。输入规模通常记作 n,表示待处理数据的数量,比如数组长度、字符串长度、图中的节点数。

估算时只数基本操作的执行次数:一次比较、一次赋值、一次下标访问都算一次。常数次操作在趋势里不重要,真正决定趋势的是 n 变大时次数怎么涨。

渐进分析(asymptotic analysis)研究的就是这种趋势:当 n 足够大,低阶项和常数系数的影响会被最高阶项压过,于是只保留最高阶项、去掉系数。`3n² + 5n + 100` 记作 O(n²)。

## O、Ω、Θ 的区别

三个记号描述同一个函数在不同方向上的界:

- **Big-O(上界)**:存在常数 c 和 n₀,当 n > n₀ 时 f(n) ≤ c·g(n),记作 f(n) = O(g(n)),含义是「最坏不会超过这个量级」;
- **Big-Ω(下界)**:存在常数 c 和 n₀,当 n > n₀ 时 f(n) ≥ c·g(n),含义是「至少是这个量级」;
- **Big-Θ(紧确界)**:同时满足上界与下界,即 f(n) = O(g(n)) 且 f(n) = Ω(g(n)),含义是「就是这个量级」。

日常说「这个算法是 O(n log n)」时,严格说用的是 Θ,因为上下界一致。只有上下界不同才需要区分,例如插入排序最坏 O(n²),最好 Ω(n)。

## 常见量级与直觉

| 量级 | 典型来源 | n = 10 | n = 1000 | n = 10⁶ |
| --- | --- | --- | --- | --- |
| O(1) | 下标访问、哈希查找 | 1 | 1 | 1 |
| O(log n) | 二分查找 | 4 | 10 | 20 |
| O(n) | 一次遍历 | 10 | 1000 | 10⁶ |
| O(n log n) | 归并、快排、堆排序 | 33 | 10⁴ | 2×10⁷ |
| O(n²) | 双重循环 | 100 | 10⁶ | 10¹² |
| O(2ⁿ) | 子集枚举 | 1024 | 超出任何机器 | 超出任何机器 |

这张表也解释了力扣上的约束:n ≤ 10⁵ 通常要求 O(n log n) 或更好,n ≤ 10³ 允许 O(n²),n ≤ 20 才考虑 O(2ⁿ) 的枚举。看到数据范围就能反推目标复杂度。

## 最好、最坏与平均

同一个算法在不同输入上代价不同。顺序查找目标在第一位是 O(1),在末尾是 O(n),平均是 O(n)。平均情况依赖输入分布的假设,不是所有输入等概率时结论会变。

工程上通常关注最坏情况,因为它给出可以承诺的上限;实时系统尤其如此。数据结构库的文档也倾向标注最坏代价,调用方才敢依赖。

## 怎么数:循环与递归

循环看嵌套层数与每层的迭代次数:

```java
int sum = 0;
for (int i = 0; i < n; i++) {          // 迭代 n 次,O(n)
    sum += arr[i];
}

for (int i = 0; i < n; i++) {          // 两层都随 n 增长,O(n²)
    for (int j = 0; j < n; j++) {
        if (arr[i] + arr[j] == target) return true;
    }
}
```

注意内层边界。写成 `for (int j = i; j < n; j++)` 时总次数是 n(n+1)/2,仍是 O(n²),系数 1/2 被忽略。

递归要写递推式再解。归并排序把数组对半切、分别排序、再合并:T(n) = 2T(n/2) + O(n),递归树每层总代价 O(n),共 log n 层,得 O(n log n)。二分查找每次砍掉一半:T(n) = T(n/2) + O(1) = O(log n)。

估算递归的一个实用办法是画递归树,数节点总数和每个节点的代价,比直接解递推式直观。

## 空间复杂度与递归栈

空间复杂度同样看增长趋势,统计额外申请的内存,不含输入本身。原地排序只用常数个临时变量,空间 O(1);归并排序需要一个等长辅助数组,空间 O(n)。

递归的内存开销容易被忽略:每次调用都会在调用栈上压入一个栈帧,保存参数、局部变量和返回地址。递归深度为 n 时,空间至少 O(n)。所以递归写得短不代表省内存,深度过大还会栈溢出。

## 一段实测对比

理论之外,实际运行一次更直观。下面两段代码判断数组里是否有重复元素,一段双重循环,一段借助集合:

```java
static boolean hasDuplicateSlow(int[] a) {      // O(n²)
    for (int i = 0; i < a.length; i++) {
        for (int j = i + 1; j < a.length; j++) {
            if (a[i] == a[j]) return true;
        }
    }
    return false;
}

static boolean hasDuplicateFast(int[] a) {      // O(n),平均
    Set<Integer> seen = new HashSet<>();
    for (int x : a) {
        if (!seen.add(x)) return true;
    }
    return false;
}
```

用一组互不相同的 20000 个整数计时,两段都会执行完整:

```java
int n = 20000;
int[] a = new int[n];
for (int i = 0; i < n; i++) a[i] = i;           // 无重复,不会提前返回

long t1 = System.nanoTime();
boolean r1 = hasDuplicateSlow(a);
long t2 = System.nanoTime();
boolean r2 = hasDuplicateFast(a);
long t3 = System.nanoTime();

System.out.println(r1 + " " + (t2 - t1) / 1_000_000 + " ms");   // false 约 100 ms
System.out.println(r2 + " " + (t3 - t2) / 1_000_000 + " ms");   // false 约 1 ms
```

具体数字随机器变化,倍数关系稳定在百倍量级。n 再大一个数量级,双重循环的耗时涨约 100 倍,集合版本只涨约 10 倍。

## 三个常见误区

- **两层循环不一定 O(n²)。** 内层若是固定次数,比如遍历长度为 26 的字母表,总次数是 26n,仍是 O(n)。看的是循环次数是否随 n 增长。
- **循环里的字符串拼接是隐式 O(n²)。** String 不可变,每次 `s += x` 都创建新字符串并复制已有字符,循环 n 次的总复制量是 1+2+...+n。改用 StringBuilder,append 的均摊代价是 O(1)。
- **忽略常数不等于常数不重要。** 复杂度描述 n 很大时的趋势;n 只有 10 时,带哈希计算的 O(n) 写法可能比朴素 O(n²) 更慢。复杂度给方向,常数和实际数据分布决定小规模下的取舍。

## 小结

- 复杂度看输入规模 n 的增长趋势,不反映绝对耗时;
- Big-O 是上界,Big-Ω 是下界,Big-Θ 是上下界一致的紧确界;
- 估算时保留最高阶项、去掉常数系数,常见量级从 O(1) 到 O(2ⁿ) 逐级变贵;
- 循环数嵌套层数与迭代次数,递归写递推式或画递归树;
- 空间复杂度计入辅助内存,递归深度会占用调用栈;
- 两层循环、循环内字符串拼接是两个高频误判点。
