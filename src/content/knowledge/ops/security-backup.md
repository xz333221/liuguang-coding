备份是“数据的另一份完整副本”，泄露一份备份等于泄露整个数据库。加密、权限与审计缺一不可，否则备份会成为最薄弱的一环。

```mermaid
flowchart LR
  A["生产数据"] --> B["备份"]
  B --> C["加密"]
  C --> D["传输(加密通道)"]
  D --> E["异地/对象存储"]
  E --> F["访问审计"]
  F --> G["定期恢复验证"]
```

## 加密

```bash
# 使用 age 加密
age -r age1... -o backup-20261126.sql.age backup-20261126.sql
```

- 备份落盘前或落盘后立即加密；
- 密钥与备份分离存放，不能放在同一台机器；
- 加密密钥纳入轮换与备份；
- 备份文件带校验和，恢复前验证完整性。

数据库自带的备份工具（如 XtraBackup）不负责加密，需要在外层处理。

## 传输与存储

- 传输使用 SSH、TLS 或专线，不要明文拷贝；
- 对象存储开启服务端加密与版本控制；
- 存储桶禁止公共读，使用最小权限的访问密钥；
- 备份目录权限 700，属主为备份账号；
- 异地保留至少一份，防止单机房故障。

## 审计

需要能回答：

- 谁在什么时间访问了哪份备份；
- 是否下载、复制或删除；
- 恢复操作由谁发起、恢复到哪个环境。

手段：

- 对象存储访问日志；
- 备份系统的操作日志；
- 服务器审计（auditd）记录敏感目录访问；
- 定期审查异常访问与权限变更。

## 保留与销毁

- 保留周期按合规与恢复需求确定；
- 过期备份自动删除，避免长期堆积扩大泄露面；
- 销毁要覆盖介质或使用云厂商的安全删除；
- 保留“最后一次成功恢复验证”的记录。

## 恢复环境的安全

- 恢复演练在隔离网络进行；
- 临时实例使用独立凭据，不接入生产；
- 恢复完成后销毁临时数据与快照；
- 恢复出的数据同样受访问控制约束。

## 常见坑

- **备份未加密**：对象存储配置失误即公开；
- **密钥与备份同机**：机器失守，两者一起丢；
- **只有备份没有恢复验证**：损坏与权限问题在上线时才暴露；
- **过期备份不清理**：历史和敏感数据长期留存；
- **恢复环境接入公网**：临时库成为新的泄露源。

## 小结

- 备份安全等级等同生产数据；
- 加密、传输保护、存储权限三者缺一不可；
- 访问审计覆盖读取、下载、删除与恢复；
- 过期备份要清理，销毁要可证明；
- 恢复演练在隔离环境进行，完成后清理临时数据。
